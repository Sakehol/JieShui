## 接水 v1.1.0 · 手机上也有「开始 / 暂停 / 结算」了

这一版把设备页做成和饮水机面板一一对应的样子，顺带修好了「点了开始却没进接水中」的问题。

### 设备页现在是四个按钮

**已就绪（阀已开，还没出水）**

主按钮「**开始接水**」，下面是「取消」。状态栏写「按机器上的「开始」，或点下方按钮」。

点「开始接水」会立刻切到「接水中 / 请按机器上的「开始」出水」，不用等下一次轮询 —— 你说的「点了开始页面没变」，就是之前要等 1.2 秒左右同步回来才变。

**接水中（已经出水）**

主按钮「**结束接水**」，下面一排「暂停 · 结算 · 取消」。

- 「暂停」→ 计时停住，状态变「已暂停」，按钮变「继续」
- 「结算」→ 走正常结算流程，进结算页
- 「取消」→ 停水并退出，不建单

### 一件必须说清楚的事

**「暂停」不会真的停水。**

我把官方 APK 的 12 个 dex 全翻了一遍，`goods/*` 下面只有 `unlock` / `sync` / `endWater` 三个端点，**没有**任何「开阀」「暂停」「继续」的接口。出水、暂停、停水这三件事，从头到尾都只能由机器面板上的实体键做。

所以：

| 按钮 | 实际效果 |
|---|---|
| 开始接水 | 只改手机上的显示，并在文案里提示你去按机器上的【开始】 |
| 暂停 | 只停住「已接 N 秒」的计时，提示你去按机器上的【暂停】 |
| 结算 | **真的有用** —— 走 `endWater` + 建单结算，等于从手机这一端结束这一单 |
| 取消 | **真的有用** —— 停水且不建单 |

这两个「真的有用」的按钮，以前只有主按钮一个，现在拆开了。

### 顺手修好的

**等待期不再莫名跳「接水中」**

上一版用 `amount > 基线` 判出水，但基线的取法有个漏洞：拿到第一个 sync 之前，`baseAmount` 是空值。现在改成「每轮都把见过的最大 `amount` 记为 `minAmount`」，只有超过它才算出水 —— 这样即使机器待命时 `amount` 不是 0，也不会误判。

**测试终于能拦住这类 bug 了**

之前所有回归测试的 mock 都把等待态写成 `identify:''`，比真机宽松；真机上 `identify` 解锁后就有值，所以「把它当出水信号」这个错在测试里永远照不出来（每次都全绿）。

现在 mock 与真机一致：`{workStatus:2, identify:'IDENTIFY_A', amount:'0'}`。旧代码跑这个 mock 会立刻失败。

### 验证

新增回归 `tools/flow_start.js`，五组断言全绿：

- 已就绪站得住（4 秒后仍是已就绪，旧代码这里已跳接水中）
- 等待期三键条只露「取消」（没水可暂停、没单可结算）
- 点「开始接水」300ms 内切到接水中，三键条出现
- 「暂停」后计时冻结（前后两次读数相同）
- 「结算」后进结算页，六行明细完整

APK 侧同样在模拟器上走通了：暂停后计时停在 10 秒不动，点「继续」恢复累加，点「结算」进结算页。

### 升级

- 网页版：刷新一次页面（Service Worker 会在后台换到 `qk-v26`，第二次打开生效）
- APK：直接覆盖安装，签名没变，老用户不用卸载

## 接水 v1.0.9 · 「接水中」现在只在真的出水后才出现

上一版（v1.0.8）我以为已经修好了，其实只修了一半 —— 你复测发现「已就绪」只维持 1 秒就跳「接水中」。这次找到了真正的判据。

### 我错在哪

判断「水有没有出来」，我先后试了两个都不对的信号：

**第一个：`workStatus === 2`**
机器屏幕上写着「设备已解锁 (6)秒 / 轻触【开始】键出水」，这个状态下 `workStatus` 就是 2。用户不按开始，它一直是 2。所以 2 的含义是「机器认得你了、阀门待命」，不是「水在流」。

**第二个：`identify` 有值**
这是 v1.0.8 换上的判据，也正是你说「只维持 1 秒」的原因 —— `identify` 是**解锁后服务端立刻就给的「建单凭据」**，扫码瞬间就有值。拿它当出水信号，等于第一次轮询（约 1.2 秒）就断定「水出来了」。

### 这次用的判据

`sync.amount` 相对**解锁那一刻的基线**有没有增长。`amount` 不是金额（单位很怪，接 0.2L 时它是 `76`），但官方正是拿它判断「这一单有没有消费」。关键是它在**待命时是个固定值**（多数机器是 0，也有的不是），只有真正出水之后才开始变大。

### 扫码后一滴水没接的文案统一了

「已就绪」状态下点取消和机器上按结算，结果都是「没接水、没花钱」，所以统一成一句：**已取消 / 本次没有接水，未产生费用**。
