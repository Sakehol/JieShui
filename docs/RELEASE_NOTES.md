## 接水 v1.1.4 · 把「接水中」这个判据改回原来那个对的

这一版没有新功能，只修一个我自己造的坑：**v1.1.3 让「接水中」彻底不出来了。**

### 到底哪里错了

v1.0.7 判断「机器有没有在出水」用的是一行很朴素的东西：

```js
const running = ws === WORK_RUNNING;   // WORK_RUNNING = 2
```

这是我们俩在真机上一起验过的，按【开始】就跳「接水中」，好用。

然后我在 v1.0.8 把它换掉了。理由写在我自己造的测试 mock 注释里一句话：「真机解锁后 workStatus 就已经是 2 了」。**这句话是我编的，从来没在真机上验过。** 基于这句假前提，我认定 workStatus 不能用来判出水，换成 `amount > 0`。

v1.1.3 我又在上面叠了一层 `status === 2`。而 `status` 的取值（1/2/4）是从官方 h5 的另一个接口 `machine/water/sync` 的 `case` 分组推出来的 —— 我们调的是 `goods/water/sync`，它到底返不返回 `status`、返什么值，同样没有在真机上验过。

于是两个都没验过的判据，把我原来验过的那个给顶掉了。真机上 workStatus 到 2 了、`status` 不是 2、`amount` 还是 0 → 三个条件全不满足 → 页面永远停在「已就绪」。

### 现在的规则

就一句话：

| `sync.workStatus` | 页面 |
|---|---|
| `0` / `1` | **已就绪** / 请在机器上按【开始】 |
| `2` | **接水中** / 正在计量 |

暂停仍然是「面板被按了一次」的推断：`workStatus` 在暂停时还是 `2`，只能靠 `sync.status` 变了没有来数。**接口不给 `status` 就认不出暂停** —— 这种情况我宁可不动，也不会像之前那样把「接水中」一起吃掉。

### 顺带的两个修正

- 所有测试 mock 里等待态的 `workStatus` 从 `2` 改回 `0`。之前写 `2` 就是上面那句假前提的产物，它让「已就绪」这一态在测试里根本不存在。
- 「接水已取消」页的按钮是 **「返回首页」**（v1.1.3 已经改了，这里同步进安装包）。这一单早就结束了，没有东西可取消。

### 出问题怎么自查

网址后面加 `?debug=1`（例如 <https://jieshui.pages.dev/?debug=1>），设备页会多出一行：

```
sync#12 status=2 workStatus=2 amount=240
```

如果「按开始还是不跳」，请把这行截给我 —— 里面就是服务端返回的原值，一眼就能看出是哪个字段没动。

- 网页版：<https://jieshui.pages.dev> 刷新一次即可（`qk-v30`）
- 安卓：直接覆盖安装本页附件 `jieshui.apk`（`versionCode 15` / `1.1.4`）

扫码、小票余额、记住登录、结算明细、防重复接水这些都没动。
