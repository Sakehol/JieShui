## 接水 v1.1.1 · 设备页跟着机器走，不再有几个按了没用的键

v1.1.0 我在手机上加了一排「开始接水 / 暂停 / 结算」按钮，想着和机器面板一一对应。真机上一用就露馅：

| 键 | 实际效果 |
|---|---|
| 开始接水 | **不会出水** —— 服务端根本没有开阀接口，出水只能按机器面板 |
| 暂停 | **完全没用** —— 同上，服务端没有暂停接口 |
| 结算 | 只等同于「结束这一单」，不是机器上那个结算 |

三个键里两个是假的，还把圆环里的字挤得顶到边上。这一版把它们全删了。

### 现在只做一件事：把机器的状态如实搬到屏幕上

扫码后手机上就四个状态，全部由机器面板驱动：

| 你在机器上做的 | 手机上显示 |
|---|---|
| 扫码（还没按开始） | **已就绪** / 请在机器上按【开始】　按钮：取消 |
| 按【开始】出水 | **接水中** / 正在计量　按钮：结束接水 |
| 按【暂停】 | **接水暂停中** / 机器已暂停（「已接 N 秒」停住） |
| 按【结算】 | 跳到结算页，六行明细 |

如果你扫码后**一滴水没接**就在机器上按了结算，或者直接点手机上的「取消」，手机上显示 **接水已取消 / 未接水，未产生费用**，并且**不会产生任何订单**。

### 「暂停」是怎么认出来的

服务端没有暂停事件，`workStatus` 在暂停时仍然是 `2`（和正在出水一样）。唯一能看出差别的还是 `sync.amount`：**连着 3 轮（约 3.6 秒）它一动不动，而机器仍在这一单里** —— 那就是暂停了。恢复出水时它又开始涨，界面自己切回「接水中」。

顺手修掉一个只有安卓端有的 bug：基线推进那行漏了，导致 `amount` 一旦涨过 0 就永远算作「还在出水」，暂停永远认不出来（网页端一直是对的）。
