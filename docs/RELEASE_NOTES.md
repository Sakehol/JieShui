## 接水 v1.1.5 · 「按了才开始」终于分得出来了

这一版只干一件事：**让「已就绪」和「接水中」真正分得开。**

### 前面三版为什么一直在原地打转

三版各错一次，错的方向还正好相反：

| 版本 | 判据 | 真机上的结果 |
|---|---|---|
| v1.0.8 → v1.1.3 | `amount` 涨了 / `status === 2` | **永远停在「已就绪」** —— 这两个信号在真机上都不按我猜的来 |
| v1.1.4 | `workStatus === 2` | **一解锁就跳「接水中」** —— 它解锁完就是 2，还没按【开始】 |

两次都栽在同一件事上：**我以为某个字段的「值」能说明机器在做什么，但它其实只说明「这一单已经开了」。**

官方 dex 里 `LockingAct` 开锁后的分流是这样的：

```
workStatus == 1  →  走先用后付页
workStatus == 2  →  直接进 StartStatusAct（接水中）
workStatus == 3  →  toast「设备工作中」
```

官方自己也认为 `2` 就是「开始了」。问题是**开始**和**出水**在机器上是两回事 —— 阀开了、屏幕亮着「轻触【开始】键出水」，人还没按，`workStatus` 就已经是 2。

### 现在的规则：不看值，看「变没变」

不再问任何字段「等于几」，只问一件事：**跟刚才比，它变了没有。**

用户每按一次机器面板，服务端返回的东西至少会有一项跟着变。所以：

- 第一次确认到变化 → 用户按了【开始】
- 再确认一次 → 【暂停】
- 再一次 → 【继续】

具体盯这三个信号，**谁先到都算**：

1. `status` / `workStatus` 拼成的签名变了
2. `identify` 从空变成有值（解锁只是开阀，按下【开始】才建单）
3. `amount` 连着两轮在涨（表在走 = 一定在出水）

新信号必须**连着两轮 `sync` 都一样**才作数。这是因为刚解锁时服务端正在登记这一单，字段自己会抖一下，那一下不能当按键。

暂停还有一条兜底：已经在出水、这一单确实走过表（`amount` 涨过基线），然后连着 3 轮不走 → 按了【暂停】。

### 顺带

- 仍然「接口不返回任何可用的变化」时，宁可停在「已就绪」不乱跳。
- 「接水已取消」页的按钮还是 **「返回首页」**。
- 所有测试 mock 的等待态 `workStatus` 统一写 `2`（真机就是这样），修正了之前「等待期写 0」的失真。

### 出问题怎么自查

网址后面加 `?debug=1`（例如 <https://jieshui.pages.dev/?debug=1>），设备页会多出一行：

```
sync#12  签名=2|2 → 2|2   status=2 workStatus=2 amount=180
```

左侧「签名=解锁快照 → 当前值」是最有用的：**按下面板时这个箭头两边应该不一样**。如果按了键它纹丝不动，说明这台机器真的不吐这个字段，那就是服务端限制，不是判据问题。
