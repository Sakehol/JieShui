## 接水 v1.1.6 · 这次是拿真机数据改的，不是猜的

这一版干的事很朴素：**把你抓的那份数据原样搬进代码，再也不猜字段含义。**

### 那份数据到底说了什么

你在真机上抓的 18 行是这样的：

```
#16 02:03:48  amount=null  identify=null                      status=6  workStatus=1   ← 还没扫码
#21 02:03:55  amount=null  identify="0620261108020353..."     status=1  workStatus=2   ← 扫完码，等你按【开始】
#29 02:04:04  amount=59    identify="0620261108020353..."     status=5  workStatus=1   ← 机器上按了【结算】
```

三条以前全猜错的：

| 字段 | 以前以为 | 真机上其实是 |
|---|---|---|
| `amount` | 出水时数字往上涨，用「涨了没」判出水 | **结算前恒为 `null`**，收口那一刻才有值。所以「涨了」这个判据永远不会触发 —— 这就是前四版一直卡在「已就绪」的真正原因 |
| `workStatus` | `2` = 正在出水 | **只表示「有没有正在进行的单」**（1→2→1）。解锁完就是 2，水一滴没出也是 2。v1.1.4 一解锁就跳「接水中」就是因为它 |
| `status` | 不知道 | **才是机器状态**：`6` 空闲没这单、`1` 闸开了等按【开始】、`2` 出水、`4` 暂停、`3`/`5` 已结算 |

### 现在的判据（三层，一层都不靠猜）

```
① status == 2      → 机器明确在出水         → 接水中
② status == 4      → 机器上按了【暂停】     → 接水暂停中
③ amount > 0       → 表上有读数：读数还在涨就是出水，连续 3 轮不动就当暂停
④ 以上都不成立      → 还是「已就绪」
```

第 ③ 层是兜底 —— 万一哪台机器中途就回填读数，也能立刻切过去，不用等结算。

另外把「秒跳」的根因也一起修了：**基线不再拿解锁后第一轮 sync 建立**。那一轮 `status` 还是 6，订单一登记就 `6→1`、`workStatus 1→2`，以前会把这个当成「用户按了开始」，页面不用人碰就自己跳。

### 你要的四个状态

| 机器上做了什么 | 手机上看到什么 |
|---|---|
| 扫码解锁，还没按【开始】 | **已就绪** / 请在机器上按【开始】 / 按钮「取消」 |
| 按【开始】 | **接水中** / 正在计量 / 已接 N 秒 / 按钮「结束接水」 |
| 按【暂停】 | **接水暂停中** / 机器已暂停 / 计时冻结 |
| 按【结算】 | 结算页六行明细（用水量、原价、小票抵扣、积分抵扣、实付、支付方式） |
| 没接水就按【结算】 | **接水已取消** / 未接水，未产生费用 / 按钮「返回首页」 |

### 还差一格

你那份数据里没有「在机器上按【开始】」那一段（当时是人不在机器旁边，扫完码直接结算的）。所以 `status == 2` = 出水、`status == 4` = 暂停这两条，是按官方语义推的，**还没在真机上直接看到过**。

如果这次按了【开始】还是不跳「接水中」，请再抓一次：进度到「接水中」那段时多点一下「标记」按钮，把 `status` 到底是几告诉我。那样第 ① 条就能改成写死的正确值。
