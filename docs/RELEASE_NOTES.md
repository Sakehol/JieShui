## 接水 v1.0.4 · 修掉「网页能扫、App 扫不出」和结算误报

这一版只做三件事，但每一件都是你实测撞到的。

### 1. 安卓扫码：两个「画面正常但一帧都不认」的坑

上一版给安卓加了"拍照兜底"，但那三个问题一起把效果吃掉了：

- **`takePicture()` 调错了线程。** 它原来是在相机派发预览帧的那条线程上被调用的，
  那条线程正在把帧交给我们，在它上面调拍照会阻塞等它自己把帧交完 ——
  轻则卡几秒，重则在部分 ROM 上**直接不再回调**。网页端的 `ImageCapture` 走独立通道，
  所以同样的逻辑在浏览器里一直没事。这就是"网页能扫、App 扫不出"的一部分来源。
- **预览尺寸用的是"请求值"而不是"实际值"。** 有些 ROM 会静默把预览尺寸换掉，
  这时给相机准备的缓冲大小就不对，相机侧**一帧都不回调，而且完全不报错**。
  现在改为回读相机真实参数，取景框也按真实尺寸排布。
- **拍完照之后预览会假死。** `takePicture()` 会清空所有回调缓冲，只调 `startPreview()`
  画面会回来但相机手上一个缓冲都没有，`onPreviewFrame` 再也不触发 ——
  表现是"拍完一张没认出来，之后彻底不动了"。现在先把缓冲交回去再开预览。

顺带把**对焦区域钉在画面中央**（不少国产 ROM 默认把对焦区域均摊到整个画面，
而我们要认的只有中间那块），并且在开闪光灯之后重新应用一次对焦参数。

### 2. 不同手机变焦倍数不一样

网页端原来写死 `zoom: 1`。但 `zoom` 在不同机型上不是一个意思：有的机型是比例（1 = 不放大），
有的是一段区间（比如 100~400），写 1 会被夹到区间下限 —— 在那些机器上恰好是 2 倍起跳。
现在先读 `getCapabilities().zoom.min` 再设，那才是这颗镜头的光学基准。

### 3. 接水一两秒就结算时，不再误报「支付还没确认」

这个是真的会误导人：界面上写「支付还没确认，去原 App 点立即支付」，
但支付宝其实已经扣款成功，点开官方 App 根本没有待支付订单。

根因是判断依据错了 —— 只看 `order/sync` 的返回值。短时接水时那几次 sync 很可能全部落空，
但扣款是异步的、已经在路上了。官方 H5 包里的订单状态表是
`0 待支付 / 1 已失效 / 2 使用中或已完成 / 3 已完成 / 4 退款中 / 5 已退款`，
**只有 2 和 3 才算钱已结清**。现在两端都改成：`order/sync` 走完再拉一次 `order/detail` 看状态，
还不确定就再等两轮。真的没消费（比如扫了码但没按机器上的开始）就明确写「本次没有产生费用」。

### 实测

`tools/ScanCoreTest.java` 在 JVM 里直接跑生产代码 `ScanCore`：

| 二维码占画面 | 1280x720 | 1440x1080 | 1920x1080 | 2048x1536 |
| --- | --- | --- | --- | --- |
| 12% | ✓ | ✓ | ✓ | ✓ |
| 10% | ✗ | ✗ | ✓ | ✓ |
| 8% | ✗ | ✗ | ✓ | ✓ |
| 7% | ✗ | ✗ | ✗ | ✓ |
| 6% | ✗ | ✗ | ✗ | ✓ |

能认出的最小占比：720p → 12%，1080p → 8%，1536p → 6%（数字越小，能站得越远）。

`tools/flow_edge2.js` 新增第 5 组用例：`order/sync` 全部返回失败、但订单 `orderStatus=3`，
结算页必须显示「费用已通过支付宝免密结算」而不是「支付还没确认」。通过。

## 安装

**网页版**（推荐，无需安装）：<https://jieshui.pages.dev>
用手机浏览器打开即可，也可以「添加到主屏幕」当 App 用。

**安卓 APK**：下载下方的 `jieshui.apk`（289 KB）。
- 与旧版签名相同，可直接覆盖安装
- 无需 root，不申请多余权限（只有相机、网络、振动）
- 首次使用需要填入你的 token —— 网页版和 APK 通用，从官方 App 里导出即可，方法见
  [技术文档](https://github.com/Sakehol/JieShui/blob/main/docs/TECH.md)
