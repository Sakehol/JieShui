## 接水 v1.1.7 · 删掉做不出来的那一屏

这一版做的事：**把「接水中 / 接水暂停中」两屏删掉，只留「已就绪」，按钮从「取消」改成「结算」。**

### 为什么删

你 11 月 8 日凌晨抓的那份数据，是我拿到过最硬的证据。开阀之后整整 20 秒，你在机器上按了【开始】【暂停】【继续】，服务端回的是：

```
#1  ~ #17   02:39:42 → 02:40:02   amount=null  status=1  workStatus=2
#18         02:40:03              amount=97    status=5  workStatus=1
```

三个字段一动不动。20 秒里 17 次轮询，一个字都没变。结算那一刻，三个字段才一起跳。

这意味着：

| 我以前的判据 | 真机上的结果 |
|---|---|
| `amount` 涨了 = 出水 | `amount` 结算前恒为 `null`，永远不涨 → 卡「已就绪」 |
| `status === 2` = 出水 | `status` 全程恒为 `1`，从没出现过 2 → 卡「已就绪」 |
| `workStatus === 2` = 出水 | 解锁后就是 2，水一滴没出也是 2 → 一解锁就跳「接水中」 |
| 「字段变了」= 按了面板 | 面板按了也不变 → 卡「已就绪」 |

**服务端根本不回传「机器上按了哪个键」这件事。** 不是判据写错，是这条数据不存在。官方 App 的接水页文案也是「点击设备上的『出水』按钮接水」—— 它自己也不做「你按了没」这个状态。

我前后五版都在同一个坑里：先假设某个字段能代表出水，再用自己写的 mock 验证自己写的判据。mock 按我的假设返回，所以每次都「通过」，一到真机就崩。这次不再猜了。

### 现在的行为

设备页只有一屏：

```
        已就绪
  请在机器上按【开始】，
    接完按下面【结算】
       [ 结算 ]
```

1. 扫码 → 开阀 → 停在「已就绪」，**不管你在机器上按什么，它都停在这儿**（因为服务端确实不告诉你）。
2. 接完水，在手机上点【结算】（或者在机器上按【结算】，页面也会自己走）。
3. 停水后，客户端问服务端「这一单花了多少」：
   - `amount > 0` → 出过水 → **结算页**（用水量、原价、小票抵扣、积分抵扣、实付）
   - `amount` 仍是 `null` → 一滴水没接 → **接水已取消 / 未接水，未产生费用**
4. 取消态的按钮是【返回首页】，不再是那个点了没反应的「取消」。

底下的「已接 N 秒」也删了 —— 数不出来就别摆着，挂着只会让人以为卡住了。

### 顺手修的

- **离开页面会自己停水**：以前点返回/关页只是走人，水还敞着；现在会静默发停水指令，不弹结算页、不建单。
- **返回键不再被拦**：既然分不出「正在出水」，就没理由锁着你了。
- **停水指令只发一次**：以前点结算时会发两遍。

### 这是退步吗

功能上少了两屏。但这两屏从来没在真机上正确出现过 —— 它们只在我写的 mock 里存在过。留着一屏会跳错、或者干脆不动的状态，比删掉更糟。

如果你后面发现**官方 App 能显示「接水中」**，那说明它走的是 BLE 通道（`machine/*` + `machineFunctionId`，dex 里有 `ShakeCommand`、`BleHelper`），和我们调的 `goods/water/sync` 不是同一套。那条路要连蓝牙，得另外做。
