## 接水 v1.1.3 · 按了机器的键，手机上终于跟着动

v1.1.2 之前，判断「水有没有出来」用的是 `sync.amount` 有没有比解锁那一刻变大。这个判据在模拟器上一直好使，在真机上一直是错的 —— **服务端直到这一单收口才回填 `amount`**，接十几秒的短单从头到尾都是 `0`。于是：

| 你在机器上按的 | v1.1.2 的表现 | 现在 |
|---|---|---|
| 【开始】 | 页面一直停在「已就绪」 | **接水中** / 正在计量 |
| 【暂停】 | 完全没反应 | **接水暂停中** / 机器已暂停 |
| 【结算】 | 页面说「接水已取消 / 未产生费用」，**但钱已经扣了** | 结算页，六行明细 |

### 换了个判据：`sync.status`

不是猜的，是官方自己的字段。两个独立来源对得上：

- h5 的 `pages_waterMachine` → `checkChannelStatus`：`case 1/2/4: return`（还在这一单里），`case 3/5` 出账，`case 6` 收口。
- dex 的 `DeviceStartupAct.lambda$38` 和 `StartStatusAct.lambda$13`：`status==3 || ==5` → 判 `amount>0 && identify` 后 `afterPay`；`status==6` → `startFault`；其余 → 1.5 秒后重新同步。

按这套语义：**1 = 已解锁等按开始，2 = 正在出水，4 = 暂停，3/5 = 本单结束该出账，6 = 设备异常。**

`amount` 不再用来判断"出没出水"，只在收口时参与「这张单要不要结算」的兜底（官方也是这么用的）。

### 「接水已取消」那个按钮

之前这一态放着的是一个亮着的「取消」—— 可这一单早就结束了，没有东西可取消，点了没有任何反应。现在改成 **「返回首页」**，点了直接回首页。

### 出问题怎么自查

网址后面加 `?debug=1`（例如 `https://jieshui.pages.dev/?debug=1`），设备页会多出一行实时显示：

```
sync#12 status=2 workStatus=2 amount=240
```

真机上如果哪个状态还是对不上，把这行截给我就行 —— 里面直接就是服务端返回的原值。
