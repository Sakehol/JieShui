## 接水 v1.0.8 · 「接水中」只在真的出水时才出现

这一版修的是状态显示：**扫码后一动没动，App 就已经在说「接水中」了。**

### 以前会怎样

扫码成功、机器屏幕刚亮出「设备已解锁 (6)秒 / 轻触【开始】键出水」，
手机上的 App 立刻就跳成了：

> **接水中**
> 水已开，正在计量

而你手上还没碰过机器。更糟的是这个状态会一直挂着，让你以为机器已经在出水了。

### 原因：`workStatus = 2` 不是「正在出水」

`goods/water/sync` 返回的 `workStatus`，官方注释里写的是「设备工作中」。
但看机器屏幕就明白了 —— 它返回 2 的时候，屏幕显示的是「**设备已解锁，轻触【开始】键出水**」。

也就是说 2 的真实含义是「**机器已认到你、阀门待命**」，不是「水在流」。
用户解了锁却一直不按开始，它照样是 2。

以前两端都拿 `workStatus === 2` 当「正在出水」，所以一解锁就报「接水中」。

### 现在怎么判断

**只有 `amount > 0` 或 `identify` 有值，才说明真的出水了。**

`amount` 不是金额（这点很早前就确认过），官方正是拿它判断「这一单有没有消费」——
一滴水没放的时候它恒为 0。所以：

- 解锁但没按开始 → `workStatus=2` + `amount=0` → 继续显示「**已就绪 / 请在机器上按「开始」**」
- 按了开始 → `amount` 变成非 0 → 这时才切到「**接水中 / 水已开，正在计量**」
- 接水中按「暂停」→ `amount` 不再增长，「已接 N 秒」也跟着停

「已接 N 秒」这个计数也改成了**只在真正出水时才累加**，暂停期间不会继续数。

### 附带修好的一处文案

以前「解锁过、但一直没按开始、机器自己收口了」这种情况，会被判成
「没有在机器上按开始，本次未接水」。现在能区分开：

- 解锁过又收口 → 「**已结算 / 机器上已结算，本次没有出水，未产生费用**」
- 从头到尾没解锁（unlock 没生效）→ 同样归到「已结算」

### 测试为什么没拦住

这一点值得单独说：mock 里「等用户按开始」那段一直写的是 `workStatus: 0`，
而**真机是 2**。mock 和真机不一致，于是「把 2 当成正在出水」这个 bug
在回归里永远照不出来 —— 每次跑都是绿的。

现在 `flow_auto` / `flow_auto_cancel` / `flow_settle_empty` / `flow_edge` / `flow_edge2`
以及 APK 的 `tools/make_test.py`，都改成了真实情况：
**`workStatus: 2` + `amount: '0'` + `identify: 空`**。

改完之后立刻红了 —— 说明这个 mock 修正本身是有效的，然后才被修好。

### 验证

- `flow_auto`：扫码后 4 秒仍是「已就绪 / 请在机器上按「开始」」，`settleCallsWhileWaiting: 0`；
  按下开始后才变「接水中」，结算行完整
- `flow_settle_empty`：解锁但没出水直接结算 → 「已结算 / 机器上已结算，本次没有出水，未产生费用」，
  `settleCalls: 0`、`hasNull: false`
- APK 模拟器实测：进设备页显示「已就绪」，几秒后仍不变；出水后才跳「接水中」，结算页六行明细正常
