## 接水 v1.0.7 · 没接水就不会弹一张假订单

这一版修的是一个很具体的场景：**扫完码、一滴水没接，直接在机器上按「结算」**。

### 以前会怎样

结算页会跳出来，标题写着「接水完成」，副标题却是
「水已停，但订单没有生成成功。请到原 App 里确认这笔订单」——
而下面「订单号」那一栏，明晃晃写着一个 **null**。

明明什么都没发生，却被通知「订单没生成成功」，还要跑去官方 App 确认一遍。

### 两个叠加的原因

**一、服务端在「没出水」时把 `identify` 返回成 JSON 的 `null`。**

代码里「这次接过水没有」的判断，一直是看 `identify` 有没有值。
问题在于安卓的 `org.json`：`optString("identify", "")` 只在**字段不存在**时给兜底值，
字段存在、值是 JSON `null` 的时候，它返回的是**字符串 `"null"`** —— 四个字母。
于是「identify 非空」恒为真，程序认定你接过水，去建订单，建不出来，
还把那个 `"null"` 当成订单号显示在页面上。

现在两边统一走一个 `str(obj, key)` 取出函数，把「字段缺失 / JSON null / 字面量 "null" / "undefined"」
一律当空串处理。

**二、你确实在机器上按了「结算」，但旧代码不认这个信号。**

以前只认「出过水」，所以按了结算它也不动，要干等到 90 秒的等待上限，
最后还反过来告诉你「没有在机器上按开始」—— 你明明按了结算，这句话当然不对。

现在多加一条判断：只要 `workStatus` **离开空闲态**（不再是 0），就说明机器那边这一轮已经结束了，
立刻收尾、不再空等。

### 现在会怎样

设备页直接显示：

> **已结算**
> 机器上已结算，本次没有出水，未产生费用

不跳结算页、不建订单、不出现 null。按钮回到「开始接水」，可以立刻接下一台。

### 回归

新增 `tools/flow_settle_empty.js`：mock 里把 `identify` 设成**真正的 JSON null**，
机器状态从 0 直接跳到 3。断言四件事 ——

- `settleLatencyMs: 4002` —— 4 秒内就收尾（旧代码会耗满 90 秒）
- `settleCalls: 0` —— 没有调用 `order/afterPay/creating`，一张订单都没建
- `state: "已结算"` / `sub: "机器上已结算，本次没有出水，未产生费用"`
- `hasNull: false` —— 结算页文本里没有漏出 `null`

原有回归（正常接水 / 主动取消 / 网络失败 / 连续两台）全部通过。
