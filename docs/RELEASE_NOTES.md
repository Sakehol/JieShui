## 接水 v1.2.0 · 一个键，两件事

> 从 v1.1.8 直接跳到 1.2.0 —— 中间没有功能变化，只是把版本号理顺：
> `1.1.x` 这一段全是「接水中」那一屏翻来覆去修的，最后确定的形态已经不是小修补了，
> 干脆给它一个像样的版本号。

这一版做的事：**把「接水中 / 接水暂停中」两屏删掉，只留「已就绪」，按钮从「取消」改成「结算」。**

### 为什么删

```
#1  ~ #17   02:39:42 → 02:40:02   amount=null  status=1  workStatus=2
#18         02:40:03              amount=97    status=5  workStatus=1
```

三个字段一动不动。20 秒里 17 次轮询，一个字都没变。结算那一刻，三个字段才一起跳。

这意味着：

| 我以前的判据 | 真机上的结果 |
|---|---|
| `amount` 涨了 = 出水 | `amount` 结算前恒为 `null`，永远不涨 → 卡「已就绪」 |
| `status === 2` = 出水 | `status` 全程恒为 `1`，从没出现过 2 → 卡「已就绪」 |
| `workStatus === 2` = 出水 | 解锁后就是 2，水一滴没出也是 2 → 一解锁就跳「接水中」 |
| 「字段变了」= 按了面板 | 面板按了也不变 → 卡「已就绪」 |

**服务端根本不回传「机器上按了哪个键」这件事。** 不是判据写错，是这条数据不存在。官方 App 的接水页文案也是「点击设备上的『出水』按钮接水」—— 它自己也不做「你按了没」这个状态。

我前后几版都在同一个坑里：先假设某个字段能代表出水，再用自己写的 mock 验证自己写的判据。mock 按我的假设返回，所以每次都「通过」，一到真机就崩。这次不再猜了。

### 现在的行为

设备页只有一屏：

```
        已就绪
   机器上点击【开始】接水
        [ 结算 ]
```

1. 扫码 → 开阀 → 停在「已就绪」，**不管你在机器上按什么，它都停在这儿**（因为服务端确实不告诉你）。
2. 接完水，在手机上点【结算】（或者在机器上按【结算】，页面也会自己走）。
3. 停水后，客户端问服务端「这一单花了多少」：
   - `amount > 0` → 出过水 → **结算页**（用水量、原价、小票抵扣、积分抵扣、实付）
   - `amount` 仍是 `null` → 一滴水没接 → **接水已取消 / 未接水，未产生费用**
4. 取消态的按钮是【返回首页】，不再是那个点了没反应的「取消」。

底下的「已接 N 秒」也删了 —— 数不出来就别摆着，挂着只会让人以为卡住了。

### 顺手修的

- **离开页面会自己停水**：以前点返回/关页只是走人，水还敞着；现在会静默发停水指令，不弹结算页、不建单。
- **返回键不再被拦**：既然分不出「正在出水」，就没理由锁着你了。
- **停水指令只发一次**：以前点结算时会发两遍。

### 这是退步吗

功能上少了两屏。但这两屏从来没在真机上正确出现过 —— 它们只在我写的 mock 里存在过。留着一屏会跳错、或者干脆不动的状态，比删掉更糟。

如果你后面发现**官方 App 能显示「接水中」**，那说明它走的是 BLE 通道（`machine/*` + `machineFunctionId`，dex 里有 `ShakeCommand`、`BleHelper`），和我们调的 `goods/water/sync` 不是同一套。那条路要连蓝牙，得另外做。

### 关于抓包里的数字

这份说明里的日志都做过脱敏：订单号前缀打码（`0620261108xxxxxx`），示例统一写成 `0620261106000000000001` 这种一眼看得出是编的。仓库里不含任何人的账号、手机号、真实设备编号或 token。

### 升级

- 网页版：<https://jieshui.pages.dev> 刷新一次即可（`qk-v39`）
- 安卓：直接覆盖安装本页附件 `jieshui.apk`（`versionCode 20` / `1.2.0`）

小票余额、记住登录、扫码、结算明细这些都没动。

### v1.1.8 顺带清理的内容（含在本版里）

- 圆环副标题从「请在机器上按【开始】，接完按下面【结算】」缩短为 **「机器上点击【开始】接水」**，不再压到圆圈边缘
- 删掉六轮改动留下的死代码：`watering` / `canLeaveDevice()` / `fmtElapsed()` 以及一批再没被读的判据变量
- 删掉 20 个一次性实验脚本（早期扫码几何、摄像头能力探测、已废弃的三键方案回归等），`tools/` 从 47 个文件收到 27 个
- 文档里指向已删脚本的段落一并更新
- GitHub 上 17 个 Release 只留 4 个节点：`v1.0.0`（首发）、`v1.0.7`（扫码点阵码那一仗）、`v1.1.2`（两入口合一）、`v1.2.0`（当前）

### 版本号说明

`v1.1.3` ~ `v1.1.8` 那六个 Release 已经删掉了 —— 它们描述的「接水中 / 接水暂停中」两屏
在真机上从来没正确出现过（服务端不返回那个信号，详见上面）。留着那些发行说明只会误导人。
仓库现在只保留四个节点：`v1.0.0`（首发）、`v1.0.7`（点阵二维码）、`v1.1.2`（两入口合一）、`v1.2.0`（当前）。
